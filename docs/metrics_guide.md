# vLLM Monitor — 指标说明

本文件解释仪表盘上每个指标的含义、来源、如何判断正常范围，以及当前哪些指标是真实数据、哪些还未接入。

---

## GPU 指标（全部来自 pynvml，真实数据 ✅）

### GPU 利用率 (%)

| 项目 | 说明 |
|------|------|
| 来源 | `pynvml.nvmlDeviceGetUtilizationRates().gpu` |
| 含义 | GPU 计算单元在一段时间内的繁忙比例 |
| 正常范围 | 0% (空闲) ~ 100% (满载) |
| 解读 | 0-20% 基本空闲，20-60% 轻度负载，60-90% 繁忙，90-100% 接近满载 |

### GPU 温度 (°C)

| 项目 | 说明 |
|------|------|
| 来源 | `pynvml.nvmlDeviceGetTemperature()` |
| 含义 | GPU 核心温度 |
| 正常范围 | 30°C (空闲) ~ 85°C (满载) |
| 警戒线 | > 85°C 可能触发降频，> 90°C 需检查散热 |
| 参考 | RTX 3060 典型满载温度 65-75°C |

### GPU 功耗 (W)

| 项目 | 说明 |
|------|------|
| 来源 | `pynvml.nvmlDeviceGetPowerUsage()` |
| 含义 | GPU 实时功耗（毫瓦转瓦） |
| 参考 | RTX 3060 TDP = 170W。空闲 < 30W，满载可达 150-170W |

### GPU 显存 (GB)

| 项目 | 说明 |
|------|------|
| 来源 | `pynvml.nvmlDeviceGetMemoryInfo()` |
| 含义 | GPU 显存使用量 / 总量 |
| 解读 | 已用显存持续接近总量 → 显存瓶颈 |
| 参考 | Qwen2.5-0.5B (< 1GB)，7B 模型约 14-16GB，13B 模型约 26-30GB |

## vLLM 指标（部分接入 ⚠️）

### 等待队列

| 项目 | 说明 |
|------|------|
| 来源 | vLLM `/metrics` → `vllm:num_requests_waiting` |
| 含义 | 等待处理的请求数量 |
| 状态 | ✅ 已接入 |
| 解读 | 队列持续 > 0 → 服务端处理跟不上请求到达速度 |

### PagedAttention 命中率

| 项目 | 说明 |
|------|------|
| 来源 | vLLM `/metrics` → `vllm:cache_hit_rate` |
| 含义 | KV Cache 命中率，越高表示越少重复计算 |
| 状态 | ⚠️ 部分接入（vLLM 0.22.1 中该指标名可能已变更） |
| 解读 | 命中率高 → 推理速度快；命中率低 → 新序列多，预处理量大 |

## 异常判断速查

| 现象 | 可能原因 | 建议操作 |
|------|---------|----------|
| GPU 利用率 100% 但功耗低 | 显存瓶颈（kernel 在等数据） | 减少 batch size |
| GPU 温度 > 85°C | 散热不足 | 检查风扇、清理灰尘 |
| 显存用量接近上限 | 模型太大 / 请求太多 | 升级 GPU / 减少并发 |
| 队列持续增长 | 吞吐跟不上请求 | 增加 GPU / 优化模型 |
| 延迟突然升高 | GC 触发 / 调度抖动 | 检查是否达到显存上限 |
